# 05 · 前端技术栈与客户端插件机制

> 回答三个问题：DSH 前端是什么、插件能否在前端做出自己的页面（选项卡形态）、能否用 React / 别的框架。
>
> 核验版本：本机 `dsh 0.1.5-rc.2`（Desktop 2.0.11，`0.1.5-rc.1` 与 `-rc.2` 在本机共存，本文以实际读到的文件路径为准）。

## 〇、三句话结论

| 问题 | 结论 | 一句话依据 |
|---|---|---|
| DSH 前端是 webview 吗？ | **是浏览器里的 Web 应用**。Desktop 只是 Electron 壳加载本机服务的页面 | `electron-runtime-CHyIF9_h.js` 里的 `await window.loadURL(spec.url)` |
| 什么语言？Vue 吗？ | **TypeScript + React 18**，不是 Vue | 前端 bundle 里 `react` 命中 69 次，`vue` **零命中** |
| 插件能做前端页面放选项卡里吗？ | **能**。右侧栏本身就是完整标签页系统，官方引导页就走这条公开路径 | `ctx.sidebarRightTabs.register()` + `sidebar.right.pane.tab` 槽位 |
| 能做 React 吗？ | **插槽正文就必须是 React**；想用 Vue 得走 iframe 变通 | 静态模块表只准入 React 运行时 |

**一条容易误解的**：「DSH 前端是 webview」这句话**对一半**。没装 Desktop 时它本来就是浏览器页面；装了 Desktop 才是「Electron 里加载同一个页面」。两种形态的前端是**同一份构建产物**，不存在两套 UI。

## 一、两层结构：壳与页面

### 1.1 Electron 壳只做壳的事

`C:\Program Files\DSH Desktop\resources\app\lib\electron-runtime-CHyIF9_h.js`：

```js
const origin = new URL(spec.url).origin;
if (isolated) await renderer.loadURL(spec.url);
else await window.loadURL(spec.url);
```

`lib/main.js`（204 KB）里 `BrowserWindow` / `loadURL` **零命中**，只有三处 `loadFile()`——`recovery.html`、`setup-wizard.html`、`profile-selector.html`。也就是说：

- **主界面**：`loadURL` 一个 URL
- **只有异常路径**（恢复、首次引导、选 profile）用本地 HTML 文件

`lib/native-ui/` 下就是那三个页面的构建产物（`recovery-*.js`、`setup-wizard-*.js`、`profile-selector-*.js` 及其 CSS/字体），与主界面完全分开。

### 1.2 URL 从哪来

| 形态 | 谁提供页面 | 说明 |
|---|---|---|
| `dsh --profile web` | `@deepseek-ai/dsh-web-app` 起的本机 HTTP 服务 | 启动打印 `dsh web:` 行，URL 携带进程 token |
| Desktop | 同一个 web-app，由 Electron 壳加载 | Desktop 的 `package.json` 同时依赖 `dsh-web` 与 `dsh-web-app` |

`dsh-web-app/README.zh.md`：找不到已构建的前端时**启动会停下并给出构建提示**，而不是渲染空白页——所以「前端没构建」是一个已知的、可诊断的失败态。

### 1.3 前端是 Vite + React 单页应用

`node_modules/@deepseek-ai/dsh-web-frontend/dist/index.html`：

```html
<div id="root"></div>
<script type="module" crossorigin src="./assets/index-BKQ_L1z6.js"></script>
<link rel="modulepreload" crossorigin href="./assets/vendor-CCJJTK99.js">
```

| 产物 | 内容 |
|---|---|
| `assets/index-*.js` | 应用骨片与启动内核 |
| `assets/vendor-*.js` | 框架与公共依赖（React 在这一份里） |
| `assets/langs/*.js` | 代码高亮按语言分包（c / cpp / csharp / css / go / rust / kotlin / python …） |
| `assets/fonts/KaTeX_*` | 数学公式字体，说明渲染链里有 KaTeX |

`langs/` 与 KaTeX 都是**按需分包**，不是全量塞进主包——这是它首帧能看的前提。

## 二、框架身份：React，不是 Vue

### 2.1 证据

| 证据来源 | 命中 |
|---|---|
| `dist/assets/index-BKQ_L1z6.js` | `react` 69 · `React` 28 · `jsx` 361 · `createElement` 12 · `useState` 13 · `vue` **0** · `Vue` **0** |
| `dist/assets/vendor-CCJJTK99.js` | `react` **0**（压缩后标志性字符串被剥掉，此处不作反证） |
| `dsh-client-ui-primitives/index.js` | `import { Fragment, jsx, jsxs } from "react/jsx-runtime"` · `from "react"` · `from "react-dom"` |
| `dsh-client-ui-renderer/client.js` | `require("react")` · `require("react-dom")` · `require("react-dom/client")` |
| Desktop `package.json` | `"react": "18.3.1"` 直接依赖；`vue` 不存在 |

> 注：`vendor-*.js` 里零命中**不能**用来证明不是 React——那是 minify 的结果。判定靠的是 `index-*.js` 的正向命中加三个包源码的显式 import。写进这份文档是为了避免下次有人拿 vendor 的数字反向推理。

### 2.2 为什么框架身份是「准入」而不是「偏好」

`dsh-client-ui-renderer/README.zh.md` 原文：

> React、React DOM、Cordis、ui-slots 与 ui-primitives 通过 Web 外壳的**静态模块表**保持**同一浏览器身份**；本包则以动态客户端 bundle 到达。

两层机制：

1. **静态模块表**：启动内核调 `modules.create({ boot: __DSH_BOOT__, staticModules: by(), loadBundle: __DSH_TRANSPORT__.loadBundle })`。`staticModules` 是外壳预置的模块集合，React 在其中——**只有一个 React 实例**。
2. **动态 bundle**：客户端插件通过 `window.__ModuleLoader__.load({ id, factory: (require) => … })` 注册，`factory` 拿到的 `require` 就从上面那张表解析。

**这条决定了插件不能自己带 React**：带了就是第二个实例，hooks 立刻炸（invalid hook call）。所以插件里永远写 `require('react/jsx-runtime')`，不写 `import`。

### 2.3 静态模块表里到底有什么

已确证在表内的（从真实插件与包源码反推）：

| 模块 | 证据 |
|---|---|
| `react` / `react-dom` / `react/jsx-runtime` | `dsh-client-ui-renderer/client.js`、tabbit `lib/client.js` |
| `@deepseek-ai/dsh-client-ui-primitives` | tabbit `lib/client.js`：`require('@deepseek-ai/dsh-client-ui-primitives')` |
| `@deepseek-ai/cordis` | `dsh-client-modules/lib/index.js` |
| `@deepseek-ai/dsh-client-modules` | 同上 |

**Vue 不在表内**——这是「插件能不能用 Vue」这一格的直接答案。

## 三、选项卡：DSH 原本就有

右侧栏（rightbar）不是「一个可插东西的位置」，它**本身就是一套标签页系统**：

- 每个会话一个 dock surface，可拖、可浮动、可分栏（最多左右两格，默认均分，分隔条限 20%–80%）
- 两种呈现形态：`push`（默认，会话区让出宽度）与 `fullscreen`（覆盖窗口，窄屏自动全屏）
- tab 条从左到右：带关闭按钮的 tab 胶囊 → 添加控件 → 分栏控件 → 面板控件

**状态只在内存**：刷新回折叠态；切会话各 dock 留在原处。

### 3.1 两步注册（公开路径）

`dsh-client-ui-sidebar-right/README.zh.md` 明说：「随包发布的引导类型走的正是别的包的类型走的**同一条公开路径**（`ui-sidebar-documentpreview` 是活的证明）」。

**第一步 · 声明 tab 类型**

```js
ctx.effect(() => ctx.sidebarRightTabs.register({
  id,          // 在全部注册里唯一；同 id 二次注册 throw（包名是天然取值）
  kind,        // 页按 kind 命名
  patterns,    // 资源类型才给：作用于 dsh-resource:// 地址的 glob
  priority,    // extension / builtin / fallback 三档，或具体优先级
  canOpen,     // (address) => boolean，否决一次命中
  title,       // (address) => string，tab chip 文字，打开时捕获
  guide,       // 引导页入口框
}), 'my-plugin: tab type')
```

**第二步 · 贡献正文**

```js
ctx.effect(() => ctx.slots.inject('sidebar.right.pane.tab', () =>
  ctx.slots.register({
    name: 'sidebar.right.pane.tab',
    key: definition.id,       // ← key 必须是类型自己的 id
    locale: NS,
  }, Body)), 'my-plugin: tab body')

// 可选：自定义标题（未注册就用打开时捕获的文本）
ctx.slots.register({ name: 'sidebar.right.pane.tab.title', key: definition.id }, Title)
```

正文组件通过框架注入的 `useTabInfo()` 读 `{ sidebar, panel, tab }`：`sidebar` 给开合与全屏信息，`panel.id` 是所在格，`tab` 含原记录字段、`visible`、`navigation`、`signal`、`actions`。

**打开它**

```js
ctx.sidebarRight.openResource(address, options?)  // dsh-resource://<type>/…
ctx.sidebarRight.openTab(kind, options?)          // 页按 kind 打开
```

已有同 `(kind, contentId)` 的 tab 会被聚焦而非重复创建（除非 `revealIfOpened: false`）；面板会自动展开，因为「用户看不到的内容不算打开」。

### 3.2 真实实现长什么样

`dsh-client-ui-sidebar-documentpreview/lib/client.js`（本机可读，6.8 MB，含按类型的正文分派）：

```js
ctx.effect(() => ctx.slots.inject('sidebar.right.pane.tab', () => ctx.slots.register({
  name: 'sidebar.right.pane.tab',
  key: TEXTPREVIEW_ID,
  locale: NS,
  store,
  children: {
    'sidebar.right.tab.document': {        // ← 声明子插槽（正文按类型再分派）
      kind: 'keyed',
      scope: 'session',
      inject: { hooks: { tabInfo: documentTabInfoFactory } },
    },
  },
  inject: (sessionId, actions) => ({ ...face(sessionId, actions), hooks: { documentPreviews: source } }),
}, TextPreview)), 'ui-sidebar-documentpreview: text body')
```

它的正文再按文件类型往 `sidebar.right.tab.document` 这个 keyed 子插槽里注册：`TextBody` / `MarkdownBody` / `HtmlBody` / `ImageBody` 各占一个 key。

### 3.3 边界

| 限制 | 后果 |
|---|---|
| 面板只在**选中会话界面**时挂载 | 没有会话就没有 dock，hero 画面右侧空的 |
| 状态**只在内存** | 刷新回默认；插件不该把持久状态放这里 |
| `kind` 上一份 `builtin` + 一份 `extension` | 多注册会 throw，这是设计不是 bug |
| `id` 全局唯一 | 同一 `id` 第二次注册 throw |
| 引导 tab 不可关闭 | 仅当它是**唯一停靠 tab** 时 |

**另外还有「中栏全局面板」**：`main` 是 root 作用域的 keyed slot，用 `ctx.layout.selectPanel(id)` 切换（`null` 回到会话界面）。但它**不是 tab**——是整屏替换，且 `conversation` 这个 key 为会话界面保留，默认组合不注册任何全局面板。想「加一个页签」应该走右侧栏。

## 四、选项卡里塞一个自己的前端页面

### 4.1 DSH 里已经有活的实现

`dsh-client-ui-sidebar-documentpreview` 的 `HtmlFrame`：

```js
const bundle = await packHtml(data, readRelative, controller.signal)
const html = createHtmlDocument(bundle)
const url = URL.createObjectURL(new Blob([html], { type: 'text/html' }))
// …
return jsx('iframe', {
  className: frameCss,
  src: url,
  sandbox: 'allow-scripts',
  title: t('frame'),
  'data-html-preview': true,
})
```

源码注释把设计意图写得很清楚：

| 注释 | 含义 |
|---|---|
| `A fixed bootstrap runs inside the opaque iframe; no Host callbacks enter its document.` | 不透明白盒，宿主不往里注入回调 |
| `Complete HTML rendered in a script-enabled opaque iframe, **without parent application access**` | 脚本能跑，父应用访问不到它 |
| `Its resource URLs are created inside the sandbox` | 资源 URL 在沙盒内生成 |
| `original-document-scoped read, **never exposed to the iframe**` | 文件读取能力不出沙盒 |

`sandbox="allow-scripts"` 而**不带** `allow-same-origin`——这正是「脚本可跑 + 完全隔离」的标准组合。`useEffect` 里配 `AbortController` + `URL.revokeObjectURL` 清理。

### 4.2 对「用 Vue 做插件页面」意味着什么

| 方案 | 可行性 | 代价 |
|---|---|---|
| **外层 tab 壳用 React，内容用 iframe** | ✅ 推荐 | 壳必须 React（槽位准入），内容框架随意。跨边界只能走 `postMessage`。需要自己解决样式跟随主题 |
| **插件自己做 Vue 运行时** | ⚠️ 理论可行、无先例 | 静态模块表里没有 Vue，得把 Vue 打进自己的客户端 bundle 再自举挂载。整包体积与首帧代价都落在插件头上，且和 React 组件树混在一起容易出微妙的生命周期问题 |
| **iframe 指外部 URL** | ❓ **未实测** | 我在 `dsh-host-webserver` / `dsh-web` / `dsh-web-app` 里**没搜到 CSP header**，但这不等于允许外链 iframe——可能是别的层设的。**置信度：中，别当结论用** |

**能确定的一条**：`iframe` + 自生成 blob URL 这条路的用法在本机有**活的、官方的实现**，不是推断——`sandbox="allow-scripts"` 这个组合在这台机器上跑得通。

### 4.3 最小客户端插件形态

本机实测 `~/.dsh/plugins/dsh-tabbit-plugin`，全部文件只有 4 个：

```
dsh-tabbit-plugin/
├── package.json        572 B   ← dsh.client.platform = "web"
├── cordis.patch.yml     63 B
└── lib/
    ├── index.js         67 B   ← 宿主侧：export function apply() {}，纯客户端插件可以空着
    └── client.js      2557 B   ← 浏览器侧：window.__ModuleLoader__.load(...)
```

`lib/client.js` 的骨架（含三处值得照抄的工程细节）：

```js
window.__ModuleLoader__.load({
  id: '@scope/my-plugin',
  factory: (require) => {
    const module = { exports: {} }
    const exports = module.exports
    const { jsx, jsxs } = require('react/jsx-runtime')
    const { IconAgentPresetOutline16, Tooltip } = require('@deepseek-ai/dsh-client-ui-primitives')

    // ① CSS 用 data 属性去重
    if (document.querySelector('style[data-plugin-css="@scope/my-plugin"]') === null) {
      const style = document.createElement('style')
      style.dataset.pluginCss = '@scope/my-plugin'
      style.textContent = css
      document.head.appendChild(style)
    }

    const NS = 'my-plugin'
    const inject = ['slots', 'locale']

    function apply(ctx) {
      // ② 字典注册进 ctx.effect → 卸载自动撤销
      ctx.effect(() => ctx.locale.register(NS, { zh, en }), 'my-plugin: dictionaries')
      ctx.slots.inject('sidebar.footer.action', () => ctx.slots.register({
        name: 'sidebar.footer.action', id: 'my-plugin-entry', order: 100, locale: NS,
      }, Entry))
    }

    exports.apply = apply
    exports.inject = inject
    return module.exports
  },
})
```

**③ CSS 变量用 `--dsw-alias-*`** 跟随主题（`--dsw-alias-label-primary`、`--dsw-alias-interactive-bg-hover`）；布局包另暴露 `--dsh-content-font-size`。

`package.json` 侧的声明：

```json
{
  "dsh": {
    "client": {
      "platform": "web",
      "immediately": false,
      "inject": ["@deepseek-ai/dsh-client-modules", "@deepseek-ai/dsh-client-ui-slots"]
    }
  },
  "exports": { "./client": "./lib/client.js" }
}
```

宿主侧 `lib/index.js` 全文只有两行（注释 + 空 `apply`）——**纯客户端插件在宿主侧留一个空 `apply` 是合法的**。

## 五、给实现者的落点建议

**要做「一个带自己页面的插件」**，最短路径：

1. 宿主侧什么都不做（空 `apply`），或只注册 agent 工具 / HTTP 路由
2. 客户端 bundle 走 `__ModuleLoader__.load()`
3. 用 `ctx.sidebarRightTabs.register()` 声明一个 tab 类型，`kind` 取包名
4. 往 `sidebar.right.pane.tab` 注册正文组件
5. 复杂内容（自带框架、第三方页面、富文档）**放 iframe**，外层壳保持小而 React

**三个最容易踩的**：

| 坑 | 说明 |
|---|---|
| 插件里 `import React` | 会拿到第二个实例，hooks 立刻报错。只能 `require` |
| 槽位注册没包在 `ctx.effect()` / `ctx.slots.inject()` 里 | 卸载时不会回滚，插件热重载后会残留 |
| 把持久状态放右侧栏 | 它只在内存里，刷新即失 |
